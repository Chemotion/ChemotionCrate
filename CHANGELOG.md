# Changelog

## 402.0.0 — 2026-11-25

First version, built on chemotion-api 402.0.0 for the ELN v4.0.2 line (verified against ELN v4.0.2). The version names the ELN line; the exact chemotion-api release is the pin (see "Versions" in the README).

- `export()`: export a Chemotion ELN collection and every collection below it as an `.eln` RO-Crate 1.2 conforming to TheELNFileFormat profile `1.2+20260923`, reading the ELN through `chemotion-api` (== 402.0.0).
- Required, validated authorship: `Author` / `AuthorAffiliation` with ORCID iD, ROR id (check digits verified) and a contact e-mail (`no-reply@eln.invalid` suggested where privacy is a concern). The authors are recorded for the crate and for every element in it, and the export says so once.
- Options `strict`, `ontology_lookup` (EBI OLS, on by default), `ols_cache`, `disclose_host`, `declare_skipped`, `progress_callback`, `interactive` (tqdm, `interactive` extra).
- `export_model()`: write a crate from an `ExportModel` without a server.
- Crate layout: elements with files as Dataset data entities in collection-independent folders, elements without files as `#`-id Datasets of the same shape, each stored once; names from any alphabet transliterated to ASCII in paths and ids (the original kept in `name`; a warning the first time); collections as contextual `Collection` entities with two-way membership; attachments as `File` entities with `sha256` and the written `contentSize`.
- chem-dcat-ap typing for reactions, their materials (one node per reaction and role, with the amounts used, pointing to the sample) and samples (with their own amounts); every other ELN v4 kind — wellplate, research plan, device description, cell line (with its material), screen (mentioning its wellplates and research plans), sequence-based macromolecule sample (with its protein), vessel (with its template), generic LabIMotion elements — as a plain `Dataset` with an ontology placeholder and its fields as `PropertyValue`s.
- Every field the ELN sends is kept (checked against the ELN's own entities, not only the client): the sample, reaction and material fields chem-dcat-ap has no place for, purification solvents, and every element's LabIMotion segments, as `PropertyValue`s, select-multi and datetime-range fields included, select and select-multi alike as option labels (the key where an option has none); generic elements and segments name the template release they were saved with (label, version, uuid); values that only restate an empty default are left out.
- Each analysis as a `Dataset` of its own (`#`-prefixed id, `about` its element, listing its files), its technique annotated as `measurementTechnique` from embedded CHMO codes, the instance's `ols_terms` vocabulary, or EBI OLS.
- Export manifest separating omissions ("This crate is incomplete": not loaded, not downloaded, absent on the server, withheld) from notes (missing metadata, a renamed path, a repeated collection, a keyword comma replaced), with counts and stable reasons; `strict` fails on omissions only. Failed attachment downloads are withdrawn from the crate. The manifest also credits, in one line, the CC BY vocabularies whose term labels the crate uses.
- Elements shared below full detail level are exported without the fields the server withheld: the mask (`***`) never becomes a value, the element is kept, and the fields are named on the element (`chemotion:withheld`) and counted in the export manifest.
- Source ELN recorded with its version and revision; host can be withheld (`https://withheld.chemotion.invalid`).
- Producer marker (`chemotion-crate` `SoftwareApplication`) carrying the versions of the packages that produced the crate.
- `read()`: open `.eln` ZIPs or extracted crates as `ElnCrate` / `ElnDataset` / `ElnCollection` / `ElnFile`, with path-traversal protection and size/compression-ratio limits; foreign crates only with `allow_foreign=True`; `source_id` is the element's ELN id (a UUID for vessels); `ro_crate_version` and `eln_version` report the versions the crate declares; ids spelled `x/` or `./x/`, and percent-encoded payload names, resolve alike.
- `chemotion_crate.patch`: fill ontology placeholders in an existing `.eln`, typing the elements as an export does (compact term, `DefinedTerm`, a `"generic"` entry for LabIMotion types).
- Vendored subset of the RO-Crate 1.2 context, regenerated by `scripts/update_context_subset.py`.
- Conformance check against roc-validator 0.11.3 and 0.13.0 and py-rocrate 0.15.1 (`just conformance`).
- The chemotion-api names it relies on are tested (`tests/test_client_contract.py`), also against the newest client release (`just client-latest`, weekly in CI).
- Live tests against a seeded ELN: export and read-back, host withholding, an element in two collections, reaction types and analysis techniques as terms, an export from a share below full detail level, cell lines, screens and SBMM samples, and the amounts the client derives (a liquid without a density, feedstock and gas product).
- Reproducible exports: the same input gives the same `ro-crate-metadata.json`, apart from the export time, in any process (keys and multi-valued literals are sorted; tested under two hash seeds), and ZIP members carry a fixed timestamp instead of the staging files' times.
